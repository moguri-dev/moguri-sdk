## Scheduled native input

Scheduling in an unbound Sandbox session may prepare an owned private stage
only under the existing explicitly enabled managed all-root capture policy.
The original command/digest, exact saved draft and scope are retained before
copy. Preparation is not a model turn, prompt admission or approval; no
model/history input exists before the original prompt is actually claimed.

The same single-root/group capture, canonical source checks, file limits,
private ownership and denied/read-only policy govern preparation. A changed
draft, account, model, policy, repository set, deletion/archive, concurrent
preparation or Stop prevents ghost admission and preserves original/partial
work. The final ghost and exact draft consumption commit together.
Existing ready stages may be verified and reused. Failed/rolled-back stages
cannot be restored or transferred by this scheduling operation.

The historic `NativeStage.turnId` ownership slot also identifies explicit
model-free preparation work; it does not create a `turn.started` event.
New preparation provenance identifies the scheduling command and saved
draft revision explicitly rather than claiming a model owner.

## Tool-less decision subcalls

Remote/native bounded-model decisions must run on their actual existing
parent SSH/native worker, never a Local controller worker. A private one-call
model operation owns its report ID, actual waiting parent request,
independent model step, complete input/output reservation, transport identity,
deadline and cancellation/terminal acknowledgement. It has no tool, hook,
filesystem, source acceptance, permission or public compound authority.

Private frames retain exact execution/report/sequence ownership through the
same atomic event/usage path before acknowledgement. They must not deadlock
behind the ordinary parent request waiting for that decision. A private-role
acknowledgement does not mean the parent worker or guest exited. Missing
usage, ownership, receipt or cleanup stays unknown/partial and cannot
continue the parent or start another paid call. Stop/control loss invalidates
both the actual parent and its owned subcall without replay.

Exact user technical/tool/steering delegation and hard policy remain separate
from model advice. Native admission must include the explicitly configured
decision model's exact credential-free resource in its reviewed provider
scope; SSH preparation uses the captured peer/account boundary. No provider,
model, credentials or endpoint is substituted. Jev/System One remains
unavailable without an enforceable upstream output/accounting contract.
The bounded-model alternative stays distinctly labeled.

## Finishing data

Remote/native finishing can use the existing parent-worker checkpoint phase
and complete prospective ledger hold at its selected boundary. It receives
only the bounded canonical aggregate already defined by wind-down policy,
not reconstructed code/history or a new task. Actual model preparation,
start, outcome, cancellation and unknown/late accounting bind that transport.

A metadata report cannot approve source, execute Git or imply task success.
Actual accepted-work publication retains its independent exact-root/user
review contract. Local commit helpers never act on a Remote/native source or
controller mapping. Any still-unqualified publication path stays explicitly
unavailable rather than borrowing the finishing hold as authorization.

## Qualification and held policy decision

Generated fixtures must prove actual SSH/native model origin, frame/hold
ownership, denied tool calls, stale source/model/policy rejection, cancellation,
concurrency, failed append, restart/lost acknowledgement and no replay.
SDK/CLI/TUI/hidden desktop must use the same typed records, and the packed
consumer and new native bytes require independent qualification.

The coordinator is obtaining the actual user's decision about native
rollback restaging. This change does not duplicate that question, transfer
roots, infer review or grant automatic restaging before their decision.
