# Workspace experience and skill gateway

## Follow-up interaction contract

The owner requires ten visible project-free root sessions, five ordinary roots
per project or captured project folder, and five children per session, with
quiet Show more/less actions. Children do not consume their root quota. Search
and selected-session reachability must remain useful; rendering limits never
change the complete service-owned sibling order, root ownership or drag intent.
Individual projects can collapse like folders without archiving or moving work.

Copy-icon success needs an actual clipboard acknowledgement, a short visible
check/Copied state and accessible status, not optimistic success or lost focus.
Failures remain explicit. Policy hints may open the actual owning setting only
when its target is known; this is navigation, never a permission grant.

The user explicitly selected ordered slash-command queueing: execute commands
when reached as commands, never as model prompt text. A second explicit choice
exempts only live stop/approval controls and `/yolo`, not view-only navigation
or theme changes. Click/Tab/key navigation remains direct. The required shared
SDK intake and service queue bind actual-user origin, captured scope,
single execution ownership, result/ack and partial/no-replay recovery.
The user also selected service-capable command execution after a client closes;
only actual UI-only actions wait for a compatible client. This is not permission
to replay an uncertain or already dispatched command.
`/yolo` chooses qualified Max when available or Autopilot and delegates session
tool approvals; it never changes model/Env, promotes read-only scope or lifts
hard policy/budget/native restrictions.

Project-folder color/removal and grouped Sandbox execution must be typed,
revision-bound service/SDK operations. Ungrouping moves navigation entries,
not repositories or captured session roots. A Sandbox folder turn leases every
actual captured root, uses only owned private copies and explicit repository
tool selection, and retains exact cancellation, accounting, publication and VM
absence. No common-parent/live-checkout mount or Local fallback is permitted.
Hide Kanban is presentation, not a new GitHub metadata request or permission
to replace a captured root/account/policy binding.

Reuse React/Electron/OpenTUI, TypeBox, maintained pi-ai, existing Node/SQLite,
clipboard bridge, inline icons, private stages and native protocol under their
current licenses. No new library, renderer or agent loop is needed. Protocol
Standalone79 used distinct `queued_slash_schema='1'`,
`project_folder_actions_schema='1'` and `sandbox_multi_root_schema='1'` markers,
alongside the independent model77 marker. Its source and generated payloads
remain preserved; its rejection of themes78 was correct for that source.

Themes/TUI landed first as main `8eca0de`. The user then authorized merging that
actual baseline into this branch, without a rebase, stack or PR merge. Actual
combined source now uses protocol80 and additionally requires genuine
`theme_catalog_schema='1'` and
`theme_model_workspace_convergence_schema='1'`. Exact genuine76, model77,
theme78 and workspace79 histories gain only their validated missing features,
in one marker/version transaction. All retained profiles are checked before
mutation. Existing ciphertext, receipts, grants, palette/custom choices,
thinking intent and hard policy remain untouched.
Preflight can read the original authenticated pre-10 project/session artifact
compartments before their independent-artifact rekeying. It does not mint a new
scope or repair a missing key; actual schema-9 failure/rollback/restart remains
recoverable before any combined marker is inserted.

Missing, corrupt or premature feature/convergence markers, unmarked77,
unknown78, falsely combined79 and future81 are refused, not repaired from a
number. Ordinary historical `command.inspected` events remain valid older
history; new slash intent uses a separate namespace. Inspection of actual
standalone79 confirms its markers reserved queued/grouped-native shapes, not a
working queue or version-3/v2 native records. Definite combined80 runtime history
and retained slash tombstones cannot be relabeled as genuine79 by erasing
theme/convergence markers. New durable shapes still
need migration/restart/concurrency/cancellation tests and exact installed/native
qualification. Protocol77 physical and standalone78 payload receipts do not
qualify changed80 bytes.

### Shared queued-command primitives

The public intake is
`sdk.commands.submit(sessionId, {client, expectedDraftRevision?, delivery?, held?})`.
It uses the existing revision-bound `message.send` transaction, not a second
queue. Actual-user slash input gains typed command metadata; worker-origin tasks,
workflow prompts and model-produced text do not acquire that authority. The
shared parser and lower-level `sdk.slash(...)` remain reusable; explicit direct
SDK dispatch is not a substitute for chat intake.

Desktop, TUI and CLI text now use this intake. The service claims the exact next
unheld command before a new model turn, retaining
`slash.command_recorded` ownership and encrypted input/result grants. Compiled
shared SDK handlers execute against the actual profile controller, including
`/model` and `/theme`, even when every text client disconnects. They do not enter
model context or invent token charges. Captured Env/root identity is rechecked
before operations and commits. Model/effort/theme preferences do not become
filesystem authority. Failed or uncertain work holds later input instead of
using an older model or replaying effects. User edits reparse exact queued
command intent; genuinely ordinary text can become a new prompt only through
that explicit edit.

Commands can also reach the head at an actual owned human-review boundary:
an exact open question/tool approval or compound validation wait, with no
in-flight inference, unrelated executing tool or native admission. This is
ordered queue scheduling, not a live-command exemption. An earlier unheld
ordinary prompt still blocks later commands. Inspection does not answer the
question or approve validation; paid follow-ups retain their existing gates.
Command activity has its own lifecycle instead of fabricating a model-running
session status or invalidating an otherwise unchanged GitHub mutation review.

UI-only results remain retained and block later work until an actual compatible
client acknowledges application. The API is
`sdk.commands.attach(client, handlers, {canApply?, onError?})`, returning
`{clientId, wake, dispose}`. Handlers are keyed by result kind or
`client-view:NAME`, receive the original immutable-profile SDK, session,
execution/input/result and AbortSignal, and return an explicit outcome.
The context also carries the original client ID and private claim.
`commands.read`, `claim`, `choose` and `complete` expose the same exact record. One client
owns at most one UI claim; its revision and private claim token cannot be
borrowed by a competing client. No handler means waiting, never raw model text,
eager navigation or fabricated success.

Stop/close, client detach and restart distinguish undispatched results from
claimed or running unknown work. Terminal work is not replayed. A disconnected
SDK drops late socket generations/invalidation frames instead of issuing new
snapshot reads. `commands.detachAll()` awaits owned view-client teardown;
intentional profile/quit handoffs can finish their original acknowledgement,
never through a replacement service connection.
Actual controller-SIGKILL coverage retains running/claimed work as partial and
holds later input. Undispatched UI results can be delivered once after restart,
but the saved queue still needs explicit Resume. A lost completion acknowledgement
cannot reapply an already committed view, even after restart.

Desktop acknowledges an actually rendered source-bound surface. TUI uses
OpenTUI's real committed renderables, frame counter and renderer-idle/output
boundary, not a new terminal parser or a `setState` callback. Clipboard/export
effects await their native acknowledgement. Editors open with their actual
revision; archive/continuation choices stay pending until the actual user
accepts or cancels them. Existing dirty-edit, question, terminal and settling
operation guards remain in force. Direct click/Tab/key navigation remains
direct. Service command results are separately retained and displayed, never
inserted into model messages. TUI `/commands` opens keyboard-readable original
history. Late text replies cannot undo Escape or a newer navigation; collapsed
conversation references do not duplicate old response bodies as fresh output.

`slash.continuation_chosen` binds the actual user, exact original input digest,
root binding and owning claim. Choosing the model atomically completes that
claim and inserts the original text/context ahead of later input, without
consuming a newer composer draft. Kanban uses its existing source/control/
budget checks and private worktree/job path, plus the same exact queue boundary.
Cancellation can restore an unchanged empty original composer only; otherwise
the newer draft stays intact and the complete original input stays retained.
An archived `/restore` has a distinct queued intake that never replaces its
saved draft or releases older held work.

Draft submission fences its own acknowledgement and buffers later typing.
Only authoritative `draft.saved.source` metadata tied to the exact original
queued execution can merge a delayed owned context capture into that newer
draft. A known revision conflict can retry once after that exact merge;
foreign text changes still require explicit conflict resolution. Neither text
similarity nor a higher revision manufactures ownership.

Unheld `/stop`, `/approve` and `/yolo` are the only live text controls. Their
`slash.live_recorded` intent/acknowledged/partial phases retain the actual user,
original input and real turn/approval target. Held versions stay inert.
`/yolo` uses real decision-provider readiness to select Max or Autopilot and
revalidates already pending tools through the existing authorization path.
Automatic delegation records its actual actor, never a remembered user grant
or a structured-question answer. Env/model/budget and hard denials do not change.
Typed `/steer` and `/interrupt` instead derive an ordered exact follow-up;
only the internal original-command executor can admit that derivation.

CLI service-capable commands finish or return an explicit queued identity.
`--hold` never runs them. `commands list/read` inspects original records without
replay. A native UI result with no actual compatible CLI handler stays
`waiting-client`, not falsely completed; supported profile/export and interactive
continuation handlers acknowledge their actual effect or user choice.

These are source integration behaviors, not physical protocol80 qualification.
The exact final SDK, desktop, native worker/image and installer still need their
own retained checks. Earlier protocol77/78 receipts remain historical evidence.

### Navigation group actions

The group action menu reuses the seven project icon colors and custom picker,
including keyboard selection, Escape and focus restoration. Optional folder
colors use `project.folder_saved`. Renaming or ordering a group preserves its
original color when no new color is supplied.

`projects.ungroup(folderId, members, expectedRevision)` binds the exact folder
revision and complete set of member project IDs/configuration revisions.
Every member returns to the standalone list and `project.folder_removed`
commits in the same event/receipt transaction. A stale, incomplete or duplicated
member set fails without moving a subset. Persistence failure rolls back every
member and the command receipt. Removal does not delete project files,
artifacts, sessions, branches or worktrees. It cannot release an unsettled root.

Captured folder chats retain their original repository identities and become
reachable under Chats after their navigation folder disappears. A later
membership change or removal never retargets those roots. Removed group IDs
cannot be recreated through the update API; a new group receives a new ID.

### Policy explanations

Known execution, tool, profile/global budget, Kupo and decision-configuration
gates can offer a link to their actual Settings section. Targets are structured
UI destinations, never guessed from provider error text. Opening a setting does
not approve work, modify policy, clear accounting, probe an execution host or
grant tools. An unqualified transport still stays blocked.

Plain help remains a text tooltip. A hint containing an action is instead a
labelled nonmodal explanation dialog, with a real button, keyboard entry,
Tab/Shift+Tab exit, Escape and focus restoration. Pointer activation clears
keyboard-only pinning even when Chromium retains `:focus-visible` from an
earlier keyboard interaction; leaving the trigger/popup does not leave a
clicked icon's hint stuck on screen. Mouse dismissal never blurs the actual
control.

Navigation uses the existing unsaved-edit and terminal-owner guards and focuses
the exact policy heading after the correct section renders. The Start dialog
can close through that same accepted navigation without starting a clone or
login. Dirty model/budget/configuration edits suppress the link and explain
what must be saved or reloaded, rather than losing a hidden draft.

## Change contract

This slice simplifies the existing macOS alpha, not the wider release roadmap.
The control plane remains authoritative for skill discovery, suggestion sources,
accounting and work observations. Clients share typed SDK queries and slash
commands. Automations is an empty left-sidebar destination. Code change and
Work item are right-rail, per-session panels, not global resources or new
provider-write capabilities. Code change preserves an already-linked PR;
Work item remains a placeholder for issue links.

Reuse React, TypeBox, the maintained MCP SDK, YAML and yauzl under their existing
MIT licenses, Node's filesystem/crypto primitives, and the existing budget,
event, terminal-owner and settings mechanisms. No new runtime dependency,
charting framework, agent loop, credential backend or terminal renderer is needed.

Protocol/schema 59 adds profile-owned optional skill-source settings and typed
read-only gateway/dashboard queries. A transactional metadata migration preserves
schema-58 events, receipts, encrypted grants and profiles. Existing settings
normalize to no configured sources. No new durable event kind is required.
User-selected source configuration uses the existing settings event and revision
check. Reading a skill cannot install it, enable a capability or grant tools.

The gateway accepts explicitly configured local folders, GitHub repository URLs
or HTTPS ZIP archives. Each find/read refreshes and validates the source; no stale
body is returned after failure. Local recursion rejects links and escaping paths.
Archives are bounded and validated without extraction or execution. Loading binds
the selected source/path and exact SHA-256 body. Sources are control-plane Local
reads, not an implicit SSH/Sandbox filesystem transport. Revocation, changed
configuration and cancellation must invalidate pending results.
Cancellation uses an authenticated, exact-profile query ID and explicit
`/v1/query-cancel` message as well as transport abort. Electron's custom-protocol
Request signal alone does not propagate renderer cancellation reliably. The
native proxy forwards the query ID and cancel route; the service aborts that
original source read, rather than only hiding its reply. A cancelled lookup
releases the settings navigation guard. A 30-second, bounded ephemeral marker
also rejects cancellation-before-admission races. IDs never identify commands,
model calls, permission grants or durable work; cancellation cannot replay or
refund any of those. Missing acknowledgement is an explicit client error.

Global suggestions preview profile-wide usage gaps and bounded prior prompts
without creating a hidden chat or calling a model. Selecting a chat narrows the
scope. Sending excerpts still requires review of the exact source digest.
Generated advice cannot apply configuration or authenticate anything.

Dashboard pages are My work, Usage, Cost and Velocity. Seven UTC days is the
initial range; 30/60/90-day presets and a custom range are available. Custom starts
at the trailing year. All-role model accounting keeps estimates, missing usage,
held capacity and invoices distinct. Velocity shows observed completions,
completion time and user interventions; these are not a causal productivity or
time-saved claim. External MCP/tool-control turns and private subagent turns
are excluded from completion/intervention velocity, not relabeled as user
tasks. Their operations and all-role costs remain in their own accounting.
Date filtering never changes cumulative budget admission.

New Local user consoles default to configured HOME, never the state directory.
Project consoles still bind the actual Moguri worktree. Existing owners retain
their original root and input is never replayed. Missing roots fail explicitly.

Settings use hover/focus copy controls for non-secret text fields and information
tooltips for explanations. Errors, live status and consequential safety warnings
stay visible. Icon-only navigation keeps accessible names and keyboard focus.
Tooltip focus follows keyboard-visible focus, not every focused element: a
mouse click must not pin a hint after the pointer leaves, and pointer-origin
focus restoration must not reopen it elsewhere. Shared and right-rail icons
use that same distinction. Keyboard hints remain visible while focused,
Escape dismisses them without blurring the control, and portalled help remains
hoverable across the existing short exit delay. Dismissal removes only the
tooltip's temporary `aria-describedby`, preserving the control and its action.
This renderer-only repair adds no dependency, service API, durable field or
protocol change.

The footer contains profile name, Ask Moguri and Settings in one row. Copilot
connection status is shown only in Settings / Models / Providers, not the left
sidebar. Both new right-rail panels follow the actual selected session.

## Session navigation follow-up

The desktop no longer offers a Global Terminal, global scope picker or a hidden
project console. Project actions open an existing session's private console at
its bound worktree; project-free sessions use configured HOME. Without an
existing session, the action asks the user to create/select one rather than
creating a hidden chat. CLI/slash entrypoints stop offering global creation.
Low-level SDK compatibility and authenticated inspection, reconciliation and
close of retained null-session consoles remain available. Removing navigation
never kills, retargets or replays an existing owner.

Reuse React (MIT), the existing native dialog, scoped reorder API, settings
events and Ghostty/PTY lifecycle. No dependency or terminal implementation is
added. Whole session rows use their upper/lower halves to reorder siblings,
including children. The grip is removed, not replaced with another button.
Context menus, Shift+F10 and Alt+Up/Down remain keyboard alternatives; attaching
to a parent remains an explicit context-menu action.

Dropping a child on a root row, its project/Chats/group header or a root-list
background requests detachment into that root group. Its original project,
workspace, Env and cancellation owner do not change. A root-row drop is a
detachment destination, not a promise of an additional reorder transaction.
Only a single organization command is committed. Sibling reordering retains
complete structural-intent checks, fresh revision CAS and the one safe retry
for a revision-only conflict.

Protocol/schema 60 adds default-on `interactions.confirmSessionDetach` and an
explicit optional detach acknowledgement on `session.organize`. An additive
