# Canonical proposals from retained roles

Current development: **0.27.0-alpha.1 / protocol and database 33**.
The qualified 0.26 internal executor and frozen 0.25 SDK/native delivery remain
the baseline. Sandbox stays paused and live personal inference stays off.

Reuse Node, maintained pi-ai, TypeBox, React/Electron/OpenTUI (MIT), existing
source capture and patch validation, the actual role ledger, independent
artifact encryption and the owned candidate jobs. System Git remains the
existing GPL-2.0-only executable. No dependency, alternate model loop, new
automatic model/workflow start, validator, filesystem permission or Git grant.

## Original model evidence, not acceptance

Resolve only a completed independently retained owned-role input with the
exact final recorded draft/revision/escalation step, successful known bounded
accounting and its original normalized tool-less result. A critic/router is
not a code proposer, and partial/stopped/failed work cannot become a completed
proposal. Parse only exact bounded patch JSON against the original selected
paths and bases. Do not repair, truncate, infer new files or relabel imports.

Read-only SDK/CLI/TUI/desktop inspection must work after source retention
without a live root, provider, credentials, inference or write. The captured
origin binds sequence input, role input/result, actual step/model/provider/API,
role index and retained source event. This says where bytes came from, not
that the model family is independent, code is correct or the user accepted it.

## Exact reviewed publication

Loading fills the local proposal editor only. Staging preview includes the
canonical role origin in its document/digest, together with original roots,
bases and exact bytes. Stage rechecks the actual retained proposal and current
source policy; omitted, swapped, deleted or edited origin cannot acquire
verified model attribution. Existing fixed-model generation origin remains
compatible and mutually exclusive.

Candidate document/record retain an immutable self-contained origin snapshot
and canonical model source. The three original sequence input, role input and
raw-result blobs gain the candidate's independent grant before effects.
Version-5 candidate exports include them; earlier formats retain their versions.
The exact staging preview discloses this separate retention in every client.
A later deletion of the source role report does not erase this separately
retained copy or refund its calls. A staged candidate
still needs a separate fresh source review and actual-user acceptance. No
automatic source write, commit, push or branch action.

Both clients preserve dirty edits and current profile/session/env/workspace/
mode/revision scope during asynchronous reads. Editing the loaded summary,
file bytes or staging root clears verified origin. An incompatible scope can
inspect retained data but cannot silently load it into another checkout.

## Schema, recovery and gates

Protocol/database 33 adds optional candidate role-origin fields and
read-only proposal queries, with the additive `candidate_role_schema` marker. Old events,
ciphertext, keys, receipts, role data and absent historical origin fields must
remain unchanged. A failed marker leaves schema 32 exactly reopenable; users
never delete state to upgrade. Copies survive independently and recovery never
replays a model, stage or source publication.

Generated tests cover actual controller/worker provenance, exact patch/base
and role index, known/unknown accounting, unavailable/foreign/deleted reports,
origin swapping and editing, fresh preview consent, separate stage/apply,
source-role deletion/reopen, immutable origin and raw migration rollback.
Shared SDK/compiled CLI/native TUI/hidden desktop and packed-consumer checks
must prove the same behavior. No public compound/family/quality or finite-kupo
readiness follows from this link.

The backend/candidate-state gate passes **21/21 in 25.62 s**, including raw
schema-32 marker failure/reopen with genuine actual-role data. Three selected
compiled CLI/shared/native TUI flows pass in **12.27 s** without another model.
Two hidden desktop flows pass in **7.9 s**, covering summary-only dirty edits,
read-only scope changes, verified loading and separate staging/application.
Both bounded desktop/compact visual rounds and the once-only mechanical scan
are complete; no further polishing is planned.

The first desktop attempt completed its functional assertions but closed the
fixture before the UI's pending/dirty protection settled, causing teardown to
time out. The fixture now explicitly observes its cleared summary and
`beforeunload` state before closing; it never disables production protection.
That failed run is retained, not counted as a pass. Complete source,
installed-consumer and exact native delivery are still pending.
