# Exact SendBox 0.2.4 qualification

This is the native-qualification slice of issue #35, not its wider loss/recovery
hardening or Milestone 1 acceptance. Historical 0.2.3 receipts and archives remain
unchanged. A current generated pass must never be reported as a physical run.

## Change contract

Reuse the service/SDK, native adapter, signed SendBox evidence, private staging,
existing generated provider fixtures and authoritative budget ledger. Node,
esbuild, pi-ai and Node-PTY are MIT-licensed; SendBox is Apache-2.0. No new
dependency, worker loop, client-only state, durable event, schema or protocol is
introduced by qualification tooling.

Retained desktop runs previously called every captured entry exact, even when
the 0.2.4 default delegated Meta ranges. Their inspection text now identifies
the captured release and distinguishes configured rules from the complete
effective destination scope, including the shared-cloud caveat. This changes
disclosure, not policy, permissions or historical 0.2.3 semantics.

Bind qualification to the actual source commit, current compiled payload,
protocol, immutable workload image, release archive/attestation, installed
host/guest bytes, trust root and release sequence. Missing physical prerequisites
are explicit skipped, unqualified gates with the required user action, never a
substitute release, administrator approval or Local fallback.

The network gate must begin with the actual selected provider's credential-free
metadata request in a fresh guest, without a warm-up or retry. Capture its
prepared endpoint and complete public CNAME ownership with the same resolver
used by managed admission. The 0.2.4 default `github.com` grant delegates GitHub
Meta domains and IPv4/IPv6 CIDRs, including shared-cloud ranges. Retain the actual
guest's effective report; a configured hostname list is not that effective scope.
Do not add another wildcard, unrelated credential or exact-host-only claim.

The worker gate must use the existing generated guest model frames through the
real service/SDK. Require actual strict tool review, retained user decisions,
complete matching model starts/completions/reservations, exact private outputs
and verified original VM absence. The generated user is a test actor, not a model
approval or a personal-account login. The real source checkout is never mounted.

Each original launch keeps its intent and evidence. Failure does not erase
partial work or replay a model/tool operation. Teardown must inspect the exact
owned guest, image, mount and launch identity. A successful CLI exit or a
worker-stopped frame alone is insufficient. Wider controller-loss, cancellation,
storage-pressure and recovery hardening belongs to the next slice.
