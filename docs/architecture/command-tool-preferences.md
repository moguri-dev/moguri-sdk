# Workflow commands and ranked integration methods

## Change contract

This user-requested follow-up starts from protocol81 and the existing shared
queued-command, workflow, suggestion, coordination and MCP APIs. Reuse Node,
TypeBox, React/OpenTUI, maintained pi-ai, the MCP SDK and Ajv under their existing
MIT/component notices, plus SQLite's public-domain terms. Presets are original
Moguri guidance, not copies of a private installed skill catalog. No replacement
agent loop or new dependency is required.

The user selected editable Settings with the factory order active immediately:
MCP via Gateway, MCP direct, REST API, then CLI. The profile-owned order is a
validated complete permutation, not a permission or proof of availability.
Native exact-root domain workflows retain their actual authority. Absent tools,
credentials or qualified execution boundaries cannot be substituted; uncertain
writes are not retried through another method. Models receive the captured
preference before request sizing, not an unsized worker-only prompt.

Direct MCP means a provider-visible leaf schema/name for an explicitly
discovered exact server tool. Execution still uses the existing service-owned
server/schema/root/account checks, tool approval, result retention and native
MCP transport. Discovery is not approval. Direct aliases cannot bypass stale
schemas, disabled servers, read-only scopes, folder/Env policy or secret
boundaries. Unsupported transports stay blocked rather than falling back.

All requested slash commands use the original service queue and actual-user
intake. Held commands stay inert. Presets keep their exact prompt and original
context; prompt-free continuation inspects retained outcomes without replaying
unknown work. `/spawn` creates and dispatches one actual owned agent child
atomically. `/orchestrate` uses existing scoped coordination, writer yielding
and metering, not navigation nesting or model-owned grants. Critique modes are
service-enforced read-only and criticize the proposal, not the person's identity.
Suggestions retain exact source review and use the actual project by default.

Protocol82 requires distinct workflow-command and tool-preference lineage.
Migration must preserve original ciphertext, receipts, controls and accounting;
new consent or direct-call provenance cannot be relabelled as older history.
Default order resolution does not rewrite old settings events.

SDK, CLI/TUI and desktop share command/capability types and persisted Settings.
Validation must cover actual workers and clients, ordering/CAS, held input,
partial/no-replay recovery, genuine migration/reopen, stale/foreign direct MCP
bindings, child cancellation and exact model/user actors. Fixtures use generated
repositories, servers and credentials only. Changed worker/native bytes require
new qualification; historical protocol81 receipts do not qualify them.

## Shared command behavior

| Command | Actual behavior |
| --- | --- |
| `/impeccable [PROMPT]` | Original Moguri UI-design guidance on the existing worker. Inspect real flows, reuse tokens/components, preserve accessibility and implement the requested UI. |
| `/continue` | No replacement prompt. Continue the retained task; pending answers/approvals remain explicit. Only a quiescent Local failure with provably undispatched workspace effects can clear its quarantine atomically. |
| `/suggestions` | Preview bounded prior prompts in the actual project, or prior project-free chats for a project-free owner. Source/model review precedes generation; `/suggestions all` explicitly widens the scope. |
| `/orchestrate PROMPT` | Retain actual-user delegation for this owning turn, create actual scoped child sessions with normal tool authorization, dispatch bounded tasks, yield shared writers and integrate results. This does not enable optional tool-less subagents globally. |
| `/spawn PROMPT` | Atomically create an owned Manual agent child, retain its original actual-user assignment, capture its root/Env/context and consume only the exact original draft when requested. |
| `/spar PROMPT` | Ask one real structured question at a time, then work from actual answers. An answer does not approve a subsequent edit/tool. |
| `/critique PROMPT` | Evidence-backed proposal/edge-case critique with service-enforced read-only tools. |
| `/roast-me PROMPT` | Sharper constructive criticism of the work, never personal abuse; the same read-only enforcement. |
| `/address-review [PROMPT]` | Protocol 112. Address review feedback on this session's pull request: fix valid points, reply on threads, never resolve them or dismiss reviews for the reviewer. Push and replies need normal approval. |
| `/fix-conflicts [PROMPT]` | Protocol 112. Merge the base into the PR branch (rebase only when the project prefers it), keep both sides' intent, ask when unclear, never force-push over others. |
| `/fix-ci [PROMPT]` | Protocol 112. Read the failing checks and logs, fix the cause instead of loosening checks, and stop to ask when a failure looks flaky or repeats. |

Workflow presets use `sdk.workflows.start`; assigned children use
`sdk.sessions.spawnPrompt`. Normal slash input still uses `sdk.commands.submit`.
Cmd/Ctrl+Enter holds the original command and attachments without running it.
When reached, the service uses that original source, not a newer composer.
Preset/assigned-child attachments are consumed once at intake; a later draft
is untouched. Neither client owns a second queue.

Safe continuation records `session.resumed.continuation` with the original
failed turn, finished event sequence and actual user actor in the same
transaction as its queue item. It does not settle unknown charges, reuse
original tool/Git requests, acknowledge partial jobs or clear Remote/grouped
uncertainty. Such cases still require original inspection and explicit Resume.

Child birth/link/task/queue/draft consumption and its receipt share one
transaction. The same retained command recovers the original child even if its
receipt is missing; a deleted original cannot authorize another child or paid
call. Delegated text is a notice with retained source, not an invented human
message in the child. Existing depth, worker-step, root-writer and aggregate/
stricter-child budget bounds still apply. The optional tool-less subagent
parallel limit remains specific to those subagents, not a new general
scheduler. Parent stop propagates through actual created children and keeps
their truthful stopped/partial outcomes and retained sessions. Grouped/Sandbox
orchestration and assigned-child commands remain explicitly blocked.

## Ranked methods and direct schemas

Settings / Integrations / MCP gateway contains **Tools and MCP / Tool preference order**.
Drag its existing handle or use Alt+Up/Down; changes autosave with revision
checks. Failed/conflicting saves retain the local order, expose an error and
require explicit save/reload. Reset resolves the factory order without
rewriting historical events.

TUI and CLI expose the same order through `/tool-preferences`, for example
`/tool-preferences cli rest mcp-direct mcp-gateway`, or
`/tool-preferences reset`. The TUI Settings list links to its current order and
editing instructions. SDK callers validate `ToolPreferencesSchema`, then use
`sdk.settings.update`/`reset` with the current exact revision. A different
profile does not inherit the edited preference.

Direct MCP changes the model-facing invocation, not the underlying MCP
connection/authentication transport. After an actually approved model
`mcp_gateway action=tools` discovery, returned leaves include `directName`.
`discover_tools` with that exact name loads its original provider-facing object
schema at the next sized model boundary. The opaque name binds server ID,
schema digest and actual root/account/transport binding. Initial bootstrap
remains three tools; direct-first preference still needs exact discovery.

The direct binding combines the complete session command root identity,
coordination peer/build and permission/policy epoch with the gateway approval
fingerprint. The server/schema fingerprint alone does not pin a Local inode or
owner. Recheck before and after asynchronous approval validation and immediately
before the connector spawn, including after credential resolution. A generated
root-inode replacement while approval waits must reject the old leaf; one
after approval but before connector dispatch must retain a partial outcome
without running the connector or retrying it on the replacement tree.

At execution, the worker and service canonicalize the captured leaf to the
same `mcp_gateway action=call`. Original provider messages/results retain the
leaf name; durable approvals, execution and public-result lookup retain the
canonical call plus captured direct provenance. Submitted provenance is
rejected. Changed discovery scope, schema/server/root, disabled servers or
revoked policy cannot reuse the old alias. A restart retains original public
results but does not restore ephemeral aliases or replay calls.

One turn captures at most 64 leaves; each schema is an unmodified object up to
12 KiB, with object property schemas. Unsupported/oversized schemas produce an
explicit `directUnavailable` reason and keep their original gateway interface;
there is no schema truncation or hidden alternative execution. Actual pinned
SSH leaves follow the existing Remote MCP approval/framing/retention path;
controller execution, access forwarding and Local fallback are not inferred.
