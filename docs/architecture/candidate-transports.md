# Reviewed candidate Env transports

Source contract: **protocol 92**, additive `candidate_transports_schema = 1`.
This extends the Local candidate/compound control plane; it does not introduce
another solver, workflow service, implicit Git publication or source acceptance.
The historical Local v1 records and their ciphertext/receipts/grants are unchanged.

## Versioned native identity repair

The user explicitly approved this acceptance repair after real released
0.2.6/Container 1.7.1 candidate reads reported guest inode **3, 2, 3** for
the same unchanged owned host directory, host device/inode
**16777229/83947482**, snapshot and authority. The old review correctly refused
the differing raw guest identities before resource creation. Ignoring those
fields or retrying until they happen to match is not a repair.

Protocol102 adds `native_candidate_identity_schema = 1`, preserving genuine101
events, encrypted blobs, grants and receipts byte-for-byte. Existing native v2
roots remain inspectable/reconcilable and cannot acquire a fabricated new
identity or fresh effects. Local v1 and pinned-SSH v2 meanings are unchanged.
New native roots are v3 and explicitly name the **controller-private-stage**
identity namespace. Their device/inode come only from the actual original
host-private stage and exact owned candidate path, never from the user's live
checkout, another profile, a VM inode or a model claim.

Before a model-free native operation uses a source or stage, its authenticated
worker reports that VM's actual canonical directory identity. The controller
checks the exact original signed execution, workspace/input/build/profile,
canonical host-private path, root ownership and retained source/stage identity,
then atomically retains a versioned per-operation grant before acknowledgement.
The grant binds both namespaces. The worker keeps the guest identity as a
same-VM replacement guard; it never compares a later VM's inode to a historical
guest inode. New stages receive their grant after their exact directory is
created, before copying source bytes or publishing an owner marker.

The durable grant is observation, not tool permission or source acceptance.
Host paths stay on the controller; only the disclosed guest path and bounded
identities cross the bridge. Fresh review still binds complete snapshot
bytes/modes, immutable source/stage ownership and current policy. Reviewed
compound tests reuse only the exact waiting parent's retained grants and
recheck its current identities before the command, not another VM's evidence.
Missing grants, failed persistence, changed paths/inodes, cancellation or loss
stay partial/blocked without fallback, new acceptance or operation replay.
Read-only recovery can retain original late evidence but cannot mint a missing
grant, relabel old v2 roots, repair effects or promote a partial result.

No dependency or additional model call is introduced. Existing MIT Node,
TypeBox, React/OpenTUI and SDK plus Apache-2.0 SendBox are reused. The shared
SDK/domain event authority supplies every client. Qualification must cover
both namespace changes with a stable host root and actual replacements/foreign
owners, failed grant storage, cancellation/loss, genuine101 migration rollback
and reopen, old-receipt preservation, exact native candidates/compound tests,
and rebuilt external-consumer/physical payloads. Earlier protocol101 physical
passes retain their original scope, not acceptance of protocol102 bytes.

The first v3 native candidate run then exposed a separate checkpoint/publication
binding defect. A stage's immutable creation `sourceDigest` is not its later
admitted `workingSource.digest`, especially after separately accepted private
candidate edits or a complete private rewind copy. New checkpoint inputs and
their canonical workspace record retain a versioned `stageBinding` for the
original stage provenance. Complete current working bytes, original Local
source bases, original stage identity and the new signed result/input remain
separate bindings. Publication verifies that explicit stage binding rather than
mistaking creation bytes for current work. Missing/changed historical bindings
still fail; old failed reports are never rewritten. The102 lineage marker also
covers these tagged checkpoint records. This does not publish an unsigned
candidate or waive the separate actual-user source review.

An existing reviewed native control source also keeps its exact workspace/input
binding through before-turn checkpoint capture. Creating a new logical admission
workspace for the same directory would silently invalidate the already reviewed
candidate stages. Control capture reads and revalidates the complete current
private tree without transferring that identity. Ordinary queued turns and
original retries still retain their distinct preparation owners; a first control
capture without a stage still requires the existing explicit preparation policy.
Changed bytes, stage identity, source or policy remain admission failures.

Native test dispatch reconstructs its state operation with the same shared
assembly used before transport admission. The retained operation digest includes
JSON field order; changing that order is not a changed user request or parent.
Original serialized digests, exact parent/SID/plan/signer checks and both
private-root grants remain required.

The complete native compound preview uses the existing 90-second native
source-review bound, not the 15-second Local/SSH metadata bound. Its two stages
each require actual independent inspect/recheck guests before any model starts.
The original shorter whole-preview timer cancelled a later guest before
bootstrap while those earlier reads were valid. This does not extend the
60-second per-guest readiness deadline, model/test limits or user-supplied
cancellation signal. Failed original starts retain their partial ownership.

Remote source/worker mechanics are exercised with an actual pinned, rootless
loopback SSH server and the real source worker/bridge. Released, user-installed
SendBox0.2.6 passes the separate protocol101 ten-gate baseline on Apple
Container1.7.1. New protocol102 candidate roots and changed worker bytes still
need their own actual physical receipt. The original source-preview failure
above remains failed; neither that earlier baseline nor a generated namespace
fixture is native candidate acceptance. No deadline, ownership, egress or
service check is weakened to obtain a pass.

The first focused protocol102 qualification passes 14 cases, including real
pinned SSH create/write/readback, changed roots, lost terminal-result storage,
new native namespace/replacement/failed-grant primitives and genuine101
rollback/reopen/downgrade refusal. The broader peer suite separately passes

## Reuse and authority

Reuse Node/TypeBox, React/OpenTUI, the maintained pi-ai transport, existing
encrypted worker journals, control-plane event authority, canonical capability
jobs, root leases, budgets and artifact retention (MIT dependencies). Native
execution remains SendBox (Apache-2.0); peer/local Git uses the existing system
Git executable (GPL-2.0). No new dependency, OS installation, model download,
provider account or hidden model loop is added.

The explicit actual-user sequence is:

1. Select the original Env/source and review workspace creation.
2. Explicitly create each owned staging resource. Compounds require two.
3. Read exact source files through the selected Env, then review and stage exact
   proposed bytes. A compound role instead pauses for a separate staging/test
   decision. Denial runs no file code and spends no critic/escalation call.
4. Inspect the retained result. A passing script or critic is advice, never code
   acceptance.
5. Obtain a fresh source/base/staged-byte/policy review and explicitly apply to
   the original source. Rejection changes proposal metadata only.

No action creates/checks out a branch implicitly, resets/merges a checkout,
commits, pushes, deletes Git resources or infers acceptance. Ordinary stages
remain independent resources when a candidate/origin session is deleted.
Archiving preserves proposals. Permanent origin deletion and exact fresh linked
PR merge retain the existing candidate-retention exception, after actual owned
work settles. Unconfirmed workers/results prevent grant deletion.

## Exact source and stage semantics

| Env | Source | Explicit stage |
| --- | --- | --- |
| Local | Original canonical managed/source Git working tree | Existing explicitly selected managed worktree, unchanged v1 behavior |
| Remote | Actual canonical Git working tree on the pinned SSH peer | New detached worktree under that peer's disclosed Moguri-owned private state |
| Sandbox | Original owned private native `/workspace` snapshot | Complete bounded regular-file snapshot copy created by the actual guest under its protected Moguri-owned state |

Remote stages bind profile/project, host-key peer digest, complete captured
target configuration, exact source root, worker build, directory identity,
Git common directory, branch and HEAD. The detached worktree is created from
that exact source HEAD with hooks/filters disabled by the existing Git helper.
Selected compound source bases must match the clean stage; dirty selected
source bytes are never silently dropped. Original source/index/HEAD and
unrelated dirty/staged bytes are not reset, staged or copied over.

Native roots deliberately have **no Git fields**. They bind the original owned
native workspace/input/configuration/build plus guest directory identities and
the complete snapshot's file-byte/mode digest. Copying is bounded by the existing
20,000-regular-file/256-MiB/32-MiB-per-file native tree limits, rejects aliases,
omits protected histories/credentials, and verifies complete source/copy
readback. This is snapshot semantics, not a fake Git worktree. No controller
Git operation or live Local source read stands in for guest execution.

Native source application writes only the original private snapshot. Publishing
native output into the live original Local Git repository remains the earlier,
separately reviewed native-publication/checkpoint contract. A private applied
candidate is not that acceptance or publication.
It also cannot retrofit an older retained signed native result: those reports
keep their original bytes. Later private candidate bytes need a fresh actual
qualified native snapshot through the existing publication flow before they
can be separately reviewed for Local publication. No extra model/VM run is
started implicitly to obtain one.

New root/document/record/result shapes are v2 for Remote/Sandbox. Local remains
v1 without invented transport telemetry. Version/Env combinations cannot
relabel old roots. Fixed-model generation and private owned-role protocols
retain their existing explicit Local contracts.

## Owned worker protocol

`candidate.operation` is a typed model-free worker start: source read, resource
creation, exact source/stage inspection, validation-state capture, or one
stage/apply file operation. It initializes no provider, has no ordinary history,
model tools, lifecycle hooks or decision-model authority.

Before effects, retain the canonical caller command, workspace/candidate job,
operation digest, complete original launch and transport-key identity.
`candidate.boundary` binds the operation digest and, for writes, the next exact
ordered file. Persist each attempt before acknowledging that boundary. The
worker rechecks directory/base/policy, writes with the expected digest, reads
back exact bytes, and then requests the matching observation acknowledgement.
Retain attempted and observed prefixes separately.

`candidate.complete` returns a bounded typed result. Persist its original frame,
cursor and result grant before acknowledging it. A standalone operation then
needs its terminal acknowledgement and actual known worker/guest cleanup before
completion. A compound side operation needs `candidate.finished` and matching
`candidate.released` from the exact waiting parent. That release proves the
operation call stack settled, not OS isolation or guest absence.

If the current Env, root, policy or cancellation authority refuses an
authenticated pre-effect authorization boundary, retain that exact frame/cursor
as partial before replying with a halt/error and acknowledging its receipt.
This acknowledgement is not an effect grant: it permits the original worker
to report its failed/stopped terminal and its actual cleanup. Otherwise the
refused cursor would make those terminal frames look like gaps, stranding
automatic eligibility reads when a source changes Env or its context closes.
Cleanup still requires the original terminal acknowledgement and known worker
exit/guest evidence; a scope change alone never proves it. Failed receipt
storage and failed post-write observations remain unconfirmed, with no cursor
skip, fabricated result, fallback or release of unknown-write quarantine.

Public non-Local model roles remain inside the original rooted SSH/native parent
with zero model tools. Their root is not described as root-less OS isolation.
Only that public compound owner can receive a bounded `candidate.start`
side operation while paused at its exact request. Private owned-model/role
transports cannot acquire that capability. The original signed guest or pinned
peer/build and all caller policy/account checks remain in force.

Both bridge and worker enforce the actual Env/source/build and canonical owned
state path. A candidate operation cannot request an arbitrary worktree,
substitute the controller, reuse a completed command/job/key, or move an
operation into a new peer/root. Existing keys and native/peer execution
directories are not replaced to recover a missing result.

## Compound roles and project tests

Cascade/Critique still use the existing bounded role holds, `model.started`/
completion transactions, original model identities, lineage review, usage
accounting and one escalation/revision limit. Full reviewed session controls
are part of immutable `policyJson`. Explicit pooled context/effort options must
fit **every complete future role/test envelope**; request preparation passes
those options without altering actual advertised model metadata or truncating
history/source/results.

Configured project scripts execute on the selected stage's actual worker, not
on the controller. Last-boundary authorization checks the exact user decision,
command, current permissions, source/stage byte state and actual owner.
Non-Local validation compares both original source state and candidate state
before/after the bounded command. Output/resource limits remain the existing
supervisor limits; over-bound context cannot be silently truncated into a
critic request. Native network or dependency/tool unavailability is a real test
failure/unqualified boundary, not permission to install or switch Env.

Local/SSH commands do not imply hostile-descendant containment. Native process
isolation is claimed only after the actual pinned native qualification. Stopped,
mutating, over-bound or cleanup-uncertain tests remain partial and cannot spend
another role or recommend a successful candidate.

## Events, retention and recovery

`candidate.workspace_recorded` projects independent ordinary resources.
`candidate.transport_recorded` binds original owner kind/ID, operation and
authority digests, immutable original launch, authenticated frame cursor,
actual signed/native or SSH observations, result and terminal/cleanup state.
Workspace/transport histories reject changed source/peer/build/command and
terminal replay. A partial transport can retain later exact receipts and
cleanup observations, but can never become completed.

Candidate-owned transport result grants belong to the candidate artifact's
retention compartment. Workspace results are independent of session retention.
Read-only transport results use only their exact originating session's grant;
their events normalize `session_id` from the immutable transport owner. Source
text is not silently accumulated in a project/profile-level result store and
is erased with its original session unless independently and explicitly retained.
Original model charges and reservations remain in their existing independent
budget compartments, including unknown completion through source deletion.

Both roots are leased using actual peer/root keys or the original owned private
root, not target aliases or Local project mappings. Ownership includes active
jobs and unresolved durable transport/resource intents across profiles and
clients. A stop-intent append failure still requests actual cancellation; it
does not claim that a stop acknowledgement was retained.

Restart marks unsettled work partial and preserves original keys, frames,
resources and possible effects. Missing result/terminal receipts and terminal
storage failures never authorize effect replay, resource deletion, source
acceptance or an extra paid call. Session/proposal deletion waits for exact
owned work; independent workspace creation is not cancelled merely because
an unrelated proposal's PR merged.

### Read-only standalone reconciliation

`candidate.transports` lists at most 100 exact retained transport records;
`candidate.transport.read` reads one original profile-owned identity.
`candidate.transport.reconcile` requires that identity's current revision and
the canonical actual-user command. It accepts no risk acknowledgement, force,
replacement key, root or target override.

Only standalone launches qualify. Attached public-compound operations retain
their original parent recovery boundary and cannot acquire standalone authority.
Reconciliation uses the original captured SSH account/key/root/build/journal,
even if current project or target configuration has changed. It never calls a
provider or launches, retries, attaches, stops or deletes a worker, VM, branch
or workspace. SSH inspection verifies the original keyed journal status proof
locally and uses the existing peer-side authenticated encrypted-frame reader.
At most two inspections, 64 receipt frames and a complete 512-KiB evidence
envelope are admitted under the bounded inspection deadline. Overlap frames
must match previously retained exact digests; gaps or changing status proofs
are rejected, not repaired.

Cleanup requires an exact complete original owned-operation result fence,
matching source/stage/proposed-byte ownership, an original terminal receipt
and authenticated known worker exit. When terminal frames were already
acknowledged/erased, the original retained controller ACK and keyed terminal
status must agree. Merely seeing a PID, an exited SSH process, an absent result
or a user assertion cannot qualify cleanup. For native records, the inspector
additionally requires the retained exact signed SID/plan/signer, original
private stage/journal and verified actual guest absence. Native inspection is
read-only and never invokes the existing stop/delete reconciliation path.
If the exact signed completion confirms rollback, SendBox may legitimately have
replaced the mounted workspace inode. The inspector then reads only that
original signed completion's unique private-store after-snapshot journal, never
the replacement live directory. The original stage-container identity/marker,
signed SID/plan/signer/command/image/time, private regular snapshot files,
original keyed status/frame authentication and bounded complete result/terminal
fences are all still required. Missing, linked, nonprivate, corrupt or ambiguous
evidence stays quarantined without live-root fallback. Recovery cannot transfer
the historical root grants into fresh filesystem or model authority.
Physical native recovery still requires its own current exact-byte evidence.

Recovered results use the original transport retention compartment. Versioned
`recovery` evidence is retained inline with `candidate.transport_recorded`;
the existing `resultDigest` transaction owns any recovered result blob.
Original controller terminal-ACK telemetry is not rewritten. The retained peer
ACK cursor and terminal-frame sequence are shown separately. The historical v1
`peerAcknowledged` bit means only that peer status is not `unconfirmed`; it is
not proof that the terminal frame was acknowledged. A known partial status can
still have an earlier ACK cursor. Clients must not label that bit a terminal ACK.
Transport, candidate, job and workspace outcomes remain **partial**; neither
source acceptance nor a lost successful command/job result is fabricated.
Canonical reconciliation-command retries return the retained identity without
another inspection. File/VM operations are never replayed.

Unknown or permanently lost/unverifiable cleanup remains quarantined and
prevents destructive retention. A partial resource whose exact standalone work
has now settled stays partial and unusable as a ready stage; it is not silently
adopted or removed. Fresh explicit work can use an otherwise unblocked source.
Partially changed source/candidate paths retain their existing inspection and
resume requirements. No accounting entry is refunded, relabeled or reconciled
by this model-free metadata action.

## Shared clients

SDK `candidates.source`, `workspaces`, `workspace`, `workspacePreview`,
`createWorkspace`, `waitWorkspace` and `stopWorkspace` expose actual typed
resources. Existing preview/stage/read/apply/reject/stop APIs keep their separate
reviews and original identities. CLI/shared TUI slash commands expose the same
operations with exact confirmation flags/JSON, never a client-owned control
plane.
`transports`, `transport` and `reconcileTransport` expose the bounded original
read-only recovery boundary; CLI/shared slash use `transports`,
`transport-read ID` and `transport-reconcile ID REV` (CLI: `--revision N`).
The desktop recovery panel labels original root/build, controller versus peer
ACK evidence, known/unconfirmed cleanup and retained partial outcomes.

Desktop Candidate/Compound panels display actual Env, root/base/build semantics,
readiness errors, retained resource state and separately reviewed creation,
staging/test and source application. Dirty input survives scope changes; a
stale review cannot retarget it. Native private application is labeled
separately from Local publication. Fixed-model/private-role panels do not gain
non-Local authority from the public compound transport.
