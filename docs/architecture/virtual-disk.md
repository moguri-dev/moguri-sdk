# Virtual disk for session worktrees

Requested by the project owner on 2026-11-17
([D47](decisions.md#d47-moguri-virtual-disk-for-session-worktrees)). An
optional, user-sized APFS sparse disk image holds new session worktrees, so
sessions can't fill the Mac. When it is nearly full, Moguri parks the oldest
archived worktrees that are clean and fully pushed, then pauses work on the
disk until space returns.

## Reused pieces and licenses

- macOS `hdiutil` (system tool, Apple) creates, attaches, resizes, compacts and
  detaches the image. No npm dependency is added.
- Node.js `fs.statfsSync` (MIT) reads free space.
- Archive cleanup's park primitive
  ([D46](managed-workspaces.md#archive-cleanup-and-restore-protocol-112)) frees
  space; the existing owned-job, intent and reconcile path records it.

## Phase 0 measurements

`npm run spike:virtual-disk` drives the production driver
(`apps/service/src/virtual-disk.ts`) against a generated 512 MiB image in a
temporary folder, with no root and no personal data. It passed on macOS arm64
on 2026-11-17:

| Step | Result |
| --- | --- |
| Create 512 MiB APFS sparse bundle | 1023 ms; 12 MB on the host while empty |
| Attach with `-nobrowse -owners on` at a private mount point | 176 ms, no root |
| Fill with generated bytes | stopped with `ENOSPC` after 496 MiB; 14.9 MB free |
| Delete the filler | free space back inside the image at once |
| Detach after the large delete | 10.46 s (APFS settles freed blocks; detach without `-force` waits) |
| Compact while detached | 64 ms; host size shrinks back (fails while attached) |
| Grow to 1 GiB while detached | 173 ms; reattach 163 ms; 1 GiB visible |
| Shrink below used space | refused by `hdiutil` (exit 22); data kept |
| Resize while attached | refused by `hdiutil` (exit 35), so resizing detaches first |

The cap is enforced by the operating system, not by Moguri accounting. Freed
space is reusable inside the image immediately but only returns to the host
after compaction while detached, which Moguri runs after every resize.

## Layout and identity

- Image: `<resource base>/virtual-disk/sessions.sparsebundle`; mount point:
  `<resource base>/virtual-disk/volume` (both private, 0700, user-owned). The
  resource base is the one captured when the store was created; moving the
  encrypted store doesn't move it.
- Inside the volume, `moguri/.moguri-disk` holds the disk ID. Mounting checks
  that marker, so another volume at the mount point is never used.
- New worktrees go to `<volume>/moguri/profiles/<profile>/worktrees/<project>/<id>`
  and record `volume: { kind: "virtual-disk", diskId }`. Every filesystem
  surface resolves the same exact path; a worktree on an unmounted disk fails
  with `virtual_disk_unavailable` instead of falling back to the state folder.
- Existing worktrees stay where they were created. Restoring a parked worktree
  recomputes its path, so it lands on the disk when the disk is on.

## Lifecycle

- **Global and root-owned.** One disk serves every profile. Its record is the
  global `application.virtual_disk_saved` event (`id`, `revision`, `status`,
  `sizeGiB`, `image`, `mountpoint`, `diagnostic`, `pressure`).
- **Create.** `application.virtual_disk.configure { sizeGiB }` with the current
  revision records `creating`, then creates, attaches and marks the image and
  records `ready`. A failed creation removes only the image it just created
  and records `failed`. If an image already exists at that path, or a restart
  interrupts creation, the disk records `off` with the reason; Moguri never
  attaches or deletes an image it didn't finish creating.
- **Resize.** Needs a `ready` disk and no running turns, writers, terminals,
  worktree jobs or candidates on it (turns waiting in the pause below don't
  count, so a full disk can be enlarged); shrinking also needs the new size to hold
  the used space plus the reserve. It records `resizing`, detaches (never
  `-force`), resizes, compacts and reattaches. Turns on the disk wait while it
  is `resizing`. A refused resize keeps the old size with a diagnostic.
- **Turn off.** `sizeGiB: null` needs no worktrees on the disk (removed or
  parked ones don't count). It records `removing`, detaches, deletes the image
  and records `off`.
- **Restart.** The disk stays mounted when the service stops, so user terminals
  in its worktrees survive. On start, Moguri mounts it if needed and checks the
  marker; failure records `unmounted` with the reason. An interrupted create,
  resize or removal is reported and never repeated.

## Pressure policy

A monitor reads free space every 5 seconds while the disk is `ready`.

- The reserve is 5% of the disk size, at least 512 MiB. Below it, Moguri parks
  archived worktrees on the disk, oldest archive first, using the D46
  conditions (all bound sessions archived, clean, head on a remote branch),
  until free space reaches the resume level (125% of the reserve).
- If space is still below the reserve, it records `pressure.paused: true`.
  Queued turns of sessions whose worktree is on the disk wait, running turns
  wait before their next model call, and new worktrees on the disk are refused
  with `virtual_disk_full`. Stop still works; a command already running can
  still hit `ENOSPC` and reports it.
- Work resumes by itself once free space is back above the resume level, for
  example after the user archives sessions whose worktrees are clean and pushed
  or makes the disk bigger. Deleting a session keeps its worktree, so it frees
  no space; remove such worktrees from project settings.
- Pause and resume are recorded only on transitions. Parking writes the usual
  worktree events. Telemetry and accounting are unchanged; a pause is not a
  failure or a budget stop.

## Clients

All clients use the SDK `application.disk.status()` and
`application.disk.configure(sizeGiB | null, expectedRevision)`.

Protocol 122 ([D76](decisions.md#d76-reviewed-profile-imports-and-live-disk-usage))
also pushes the disk's status on the event connection: a `disk` frame follows
`ready` and is sent again whenever the disk's state changes or the monitor sees
free space move by at least 0.1% of the disk. Every profile's clients receive
it, because the disk is root-owned. The SDK keeps the last frame in
`ClientState.disk` (`application.disk.current()`), so clients show live usage
without polling. Usage moves within one monitor interval of a worktree being
created or removed.

- Desktop: **Settings / Retention / Session disk** has a switch and a size
  select (5 to 500 GB) that save immediately, with a live usage bar above the
  summary and diagnostics. The sidebar shows the same bar, without text, above
  the service status while the disk is on. A chat whose worktree is on a
  paused disk shows a notice above its composer.
- TUI and CLI: `/runtime disk`, `/runtime disk-size GB`, `/runtime disk-off`;
  `moguri storage disk status|size GB|off`. The TUI shows the disk's usage in
  its status line while the disk is on, and a notice when the current chat
  pauses.

## Not covered

- Remote and Sandbox sessions don't use the disk; their roots live elsewhere.
- The encrypted store, dependency cache, speech models and worker images stay
  outside the disk and outside its limit.
- Hosts without `hdiutil` (Linux) report the disk as unsupported.

## Evidence

- `tests/virtual-disk.test.ts`: real `hdiutil` on macOS creates a 1 GiB disk,
  puts a new worktree on it, pauses a queued turn and new worktrees when full,
  resumes after space returns, parks an archived pushed worktree under
  pressure, resizes to 2 GiB with worktrees intact, refuses turning off while a
  worktree lives there, then turns off and removes the image. Generated-driver
  cases cover unsupported hosts, busy resizes, too-small shrinks and stale
  revisions without touching the image.
- `tests/e2e/settings-preferences.spec.ts` checks the Retention controls.
- Schema 112 refuses to relabel histories with the disk event as pre-112.
