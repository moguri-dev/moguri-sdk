# Compound routing prerequisites

Current **0.22 development** keeps protocol 27; the delivered SDK/app remain
immutable **0.21.0-alpha.1**. This private proof does not expose Cascade,
Critique, candidate application or finite kupo budgets. Sandbox stays paused.

Reuse maintained pi-ai, Node/abort and TypeBox (MIT), the existing actual
request/context estimator and endpoint-boundary checks. No dependency,
alternate production agent loop, personal model account or paid inference.
The existing generated Single transport baseline passes **8/8 in 414.86 ms**,
with its actual two-request exchange measured at **51.86 ms**.

Private compound roles must use an exact eligible policy/model snapshot,
canonical identity and explicit different-family critic metadata. Alias names
alone do not establish independence. All actual requests are tool-less,
bounded and acknowledged/recorded before another leg. Unknown usage remains
unknown; malformed advice, failed receipts, stale eligibility, denied
admission, output-bound violations and cancellation stop continuation.
Classifier explanations never become solver instructions or user answers.

Cascade permits one explicitly configured escalation after explicit validator
evidence, never an invented provider or privacy boundary. Critique uses one
independent read-only critic and at most one bounded revision by the bound
solver. Candidate, critic and validation text are untrusted data. Passing
these mechanical gates returns only a **proposal**, not user acceptance,
permission, verified quality, a filesystem effect or an applied patch.

Owned candidate workspaces, base-checked reviewed application, independent
durable artifacts, real worker/ledger role ownership, complete cancellation/
restart and shared SDK/native clients remain separate admission gates.
Finite routes additionally require reserved wind-down capacity and an
actually authorized accepted-work checkpoint/commit, including denied/failed
cases. No extra finishing model call may exceed a cap. These private
transport checks cannot qualify those requirements or calibrated thresholds.

The first shared-transport refactor used the Moguri normalized usage field
on pi-ai's native result, producing three clear failures and a type error.
Native pi-ai uses `usage.output`; the established control-plane mapper
confirms that distinction. Records are retained before output-contract
validation, and no failed run is treated as a qualification.

## Generated transport measurements

Run `node scripts/compound-routing-spike.mjs`. The final combined Single/
Cascade/Critique gate passes **20/20 in 454.56 ms**, with both type checks and
the full product build. The generated efficient Cascade proposal takes
**59.73 ms**; independent critique plus one revision takes **7.41 ms** after
fixture warm-up. These loopback timings are not live latency or a calibrated
comparison of model quality/performance.

Each generated role reports 42 total/12 output tokens; per-call request time
and actual prepared canonical model ID are retained. Billed USD stays null.
Actual context sizing and prepared URL/identity are checked after metadata
selection and before dispatch. Every request is tool-less with zero automatic
provider retries. Synthetic family metadata tests mechanical identity rules,
not empirical independence of real model weights.

Coverage includes no classifier-reason promotion, a single escalation/revision,
reject/invalid final validation, missing/same-family/aliased critic, malformed
router/critic advice, duplicate/protected/unbased patches, lossy Unicode,
actual identity/endpoint/
context disagreement, failed role admission/completion receipt, changed policy,
unknown/over-limit metering and actual in-flight critic cancellation. No
candidate is accepted or applied by these results. Owned worker/ledger/candidate
workspaces/review/application, reserved wind-down/authorized checkpoint and
exact SDK/native delivery remain required before public admission.

The subsequent [owned candidate file probe](candidate-primitives.md) connects
generated Cascade/Critique proposals to one actual SDK worktree stage and a
separate exact-review application. It qualifies bounded file mechanics, not
the production worker/lease/actor/ledger, durable recovery or public workflows.
