# Routing transport prerequisite

This is the historical pre-integration Single proof. The later
[owned Single implementation](routing.md) is qualified separately; current
[compound transport evidence](compound-routing-primitives.md) still does not
enable public Cascade or Critique. The original stage below describes its
then-current boundary, not the current Single API.

Historical status: generated Single-pattern primitive only. No public kupo selection,
automatic pattern, coding candidate or new provider is enabled. The qualified
0.9 app/SDK artifacts remain unchanged.

Reuse maintained pi-ai (MIT), TypeBox (MIT) and Node HTTP/abort primitives
(MIT). The isolated prototype uses the real maintained streaming adapter
against generated loopback providers. It adds no durable product schema,
alternate agent loop, per-client provider payload or implicit model account.

## Generated evidence

Run `node scripts/routing-spike.mjs`.

Eight checks pass in **333.86 ms**. The successful classifier-to-solver
exchange takes **46.84 ms**, with exactly two tool-less requests:

| Role | Actual forwarded output bound | Generated reported total |
| --- | --- | --- |
| router | 128 | 42 |
| solver | 64 | 42 |

These are loopback fixture measurements, not model quality, live latency,
pricing, a billing guarantee or a full durable accounting qualification.
Billed USD remains unreported. Role admission/completion hooks are tested,
including blocked continuation after a failed receipt; wiring those hooks
to the authoritative session/profile/global ledger is still required.

Eligibility is captured before classifier input: explicit approved solvers,
configured classifier, declared env/access/context/image capabilities and
hosted-data permission. Missing/foreign/ineligible models produce an error,
never a Local or hosted fallback. At most eight approved solvers are accepted.
The classifier sees only filtered public metadata, not credentials or
provider payloads. Eligibility is rechecked after asynchronous model
preparation/admission and before the next request.

An exact JSON Single plan must name a member of that snapshot, remain within
numeric/string bounds and meet the configured fixture threshold. It cannot
introduce an endpoint or switch to an unqualified Cascade pattern. That
threshold is not a calibrated confidence guarantee. Classifier explanation
is not copied into the solver's instructions or promoted to user context.

The checks retain classifier telemetry even when the plan is rejected.
Unreported usage stays unknown, not zero. Failed completion receipt, zero role
admission or a changed pool stops before another request. Cancellation of an
actual classifier HTTP exchange cannot launch the solver or return a successful
route. These transport-only results do not prove provider-side cancellation.

## Still required before feature admission

The production permission-aware worker must own each actual role, immutable
policy/plan snapshot, model/version binding and context provenance. Every call
needs the existing atomic reservation/completion acknowledgements and truthful
stop/restart/replay behavior. An explicit fixed model must stay fixed.

Cascade and critique/revision additionally require actual owned candidate
workspaces, independent critic family, bounded validation/revision/escalation,
base-checked accepted-patch application and preservation of unrelated user work.
Model statements that a candidate is acceptable are not validation or Git
permission. Finite kupo budgets need reserved wind-down and an actually
authorized accepted-work checkpoint attempt. None is qualified by this probe.

Shared SDK/TUI/desktop selection, all supported envs, candidate review,
durable migration/recovery and complete local/hosted generated evaluation
remain product work. kupo stays unavailable until its exposed subset satisfies
those contracts.
