# Native retry restaging and reviewed transport checkpoints

Status: protocol86 implementation. Protocol84/85 installers, encrypted history,
model receipts and native image evidence remain immutable predecessor evidence.

The actual user enabled the product boundary for exact private-snapshot retry
restaging under an explicit policy. This does not enable that preference in any
profile automatically. The user separately selected native accepted-work Git
publication to the original Local source repository only after actual-user
native-source acceptance. Neither decision is model advice or a policy override.

## Change contract

Reuse maintained pi-ai, TypeBox, Node crypto/filesystem/IPC, signed native
snapshots, the existing worker/transports, writer leases, encrypted event store,
all-role ledger and reviewed temporary-index Git helper. Libraries retain their
existing MIT licenses; system Git is GPL-2.0-only. No new provider, model loop,
queue, secret backend or permission authority is introduced.

Protocol86 adds independent provenance markers for native retry restaging and
transport accepted-work checkpoints. Genuine85 migrates both atomically;
missing, premature or downgraded provenance fails before mutation.

## Snapshot-only retries

Factory policy is off. A qualifying new native retained request binds its actual
execution/workspace/input and original private root. Restaging requires exact
profile/session/turn/model/request ownership, unchanged current authorization,
permissions and Env, verified original guest absence and a complete verified
signed after-snapshot. An acknowledgement is not verified cleanup.

Copy only that original immutable private snapshot, excluding protected runtime
control/credential state. Verify every regular-file byte and supported mode and
the complete bounded file set before binding a new private stage. Never capture
the live checkout, silently omit retained work, follow a different execution,
replay old tools/Git/hooks or refund unknown charges. Retain preparation intent
before copying. Stop, changed scope, failed copy, lost receipt and restart
preserve partial work without replay.

The new stage retains original execution/snapshot/request provenance. Original
request/context, queues and drafts stay unchanged. Every real recovery call gets
its own normal all-role admission. Legacy requests without qualified restaging
provenance keep their explicit inspection gate.

## Separately reviewed checkpoints

Native source acceptance is its existing exact actual-user publication receipt,
not finishing-model output. A subsequent checkpoint explicitly discloses Local
Git publication to that original canonical repository. Review exact accepted
files, modes, original source/root, HEAD/index, new non-protected branch, message
and current policy. Preserve checkout/index and record intent before effects.
No Local model call, substituted checkout, push, merge or reset is authorized.

Remote checkpoint Git runs at its captured SSH peer/root through an owned
model-free operation. Both paths require current policy, writer leases and
independently retained actual-user source acceptance. Partial publication, unknown
cleanup, deleted source grants, late results and restart cannot create success or
replay another operation. Metadata finishing alone remains insufficient.

Remote source acceptance is a separate immutable actual-user input grant.
Git retains independent reviewed branch/base/message/files and unique peer-key
intent before dispatch. The original encrypted peer journal records intent,
prepared object, published ref, result and a terminal effect fence. Inspection
requires contiguous authenticated receipts plus fresh original source/index/HEAD
and exact ref/blobs/modes; it never infers process ownership from a PID. A known
terminal Git call stack is an effect fence, not a claim that every peer process
or detached descendant has been proven absent.

Attempted partial v3 checkpoints keep an independent exact-root lease and block
report deletion/archive, owner deletion/archive and project removal until fresh
explicit effect inspection. A read query alone cannot clear that lease.
Revision/digest-bound `winddown.commit.reconcile` retains an actual-user
inspection grant atomically without changing the original partial job,
diagnostic, Stop, accepted bytes, model receipts or unknown charges. Missing
terminal fences, changed refs/source and failed inspection/persistence keep the
lease. A generic Resume cannot discard it, and restart never reissues Git.
Legacy v2 metadata-only reports cannot acquire this authority.
