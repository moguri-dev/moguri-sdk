# Owned tool-less role continuation

Status: private **0.24 development / protocol 31** prerequisite. This extends
the existing real Node worker's private candidate-stage acknowledgement
protocol, not public Cascade/Critique admission, a durable compound workflow,
model-family/quality qualification, a second model loop or automatic acceptance.
The immutable 0.23 delivery is unchanged; Sandbox stays paused and live personal
model calls remain off.

Reuse maintained pi-ai, Node/abort/IPC and TypeBox (MIT), the existing worker,
bounded requests, normalized results, private context and planned-capacity
ledger. No dependency, durable event/schema/migration or client command is
added. Current fixed-model generation still acknowledges one call without
continuation and remains one call.

## Completion is a barrier

Every model completion now requires an actual `accepted: true` host
acknowledgement before success, tools or another role. Missing/rejected
acknowledgements are failures, not success-shaped defaults. Existing normal
solver, Single, compaction and generation hosts already send this explicit
acknowledgement after their durable transaction.

Only an owned router or candidate phase can request `continue: true`.
Candidate continuation additionally requires exact read-only ownership and
a null filesystem root, one complete tool-less result, valid reported total/
output tokens and an actual positive safe output bound within the prepared
model capacity. Unknown metering, output violations, length/deferred/error
results and tool calls cannot authorize the next paid role even if the host
mistakenly approves them. Stop is rechecked before continuation.

Continued output is not appended to ordinary worker context. Each later host
boundary supplies its exact role context; it does not inherit router/critic
instructions by accident. The same worker PID, abort ownership, zero automatic
provider retries and 32-step bound apply to all roles. There is no recursive
`kupo` call or model-selected endpoint.

This private transport capability does not select a workflow, model pool,
critic, candidate, validator or permission. A production caller must retain
its complete immutable role policy/input/model scope, role budget/start,
actual result and accepted transition before authorizing continuation. Model
advice still cannot become user acceptance or approval.

## Generated actual-worker qualification

`node scripts/compound-routing-spike.mjs` includes the previous generated
transport gates and actual existing-worker probes, not another production
agent implementation. The probe's endpoints, role labels and contexts are
generated; they do not establish real model-family independence or quality.

The root-less read-only worker actually performs three bounded, tool-less
requests in one process, each with explicitly supplied canonical context.
Earlier output is absent from later contexts unless a future controller
explicitly includes it as untrusted data. Holding acknowledgement keeps the
next request at zero; failed persistence, rejected/missing acknowledgement,
invalid scope, unknown/over-limit/incomplete/tool output, stop and control loss
halt paid continuation. A requested 33rd role stops at exactly 32.

A separate fixture host connects those same actual worker messages to real
version-1 planned holds. Complete role capacity is recorded before execution;
each exact entry/consumed-plan/model-start transaction precedes a reply with
inference access. Actual normalized results and charges commit before the
next acknowledgement. Three genuine loopback roles retain **126 reported
tokens**, with billed USD null. Injecting real completion-insert failure
dispatches only the first call, retains its **99-token unknown hold** and
releases unused plans on exact owner termination. Reopen preserves the ledger
without replaying a request.

These are mechanical host/worker/ledger interoperability results. The fixture
host is not a completed control-plane compound scheduler. Immutable workflow
ownership/recovery, original intent, source-bound candidate and critic/revision
contracts, actual eligible family/privacy policy, unknown-future input bounds,
policy-authorized accepted-work wind-down, SDK/native UX and real quality
remain separate gates. Public finite kupo remains blocked.
