# Home-backed project-free Local chats

The user explicitly selected Home, matching the existing private chat-console
default, as the working directory for ordinary project-free chats. A null
project remains a real null project: never create a synthetic project, borrow
the last checkout, assume a repository or turn this binding into a tool grant.

## Authority and reuse

Reuse Node/Node-PTY, the existing file/command/data executors, typed SDK,
TypeBox, React/OpenTUI, Ghostty and authenticated browser/MCP brokers under
their existing MIT/component notices. Add no dependency, shell executor,
browser-control bypass or new execution transport. Local stays subject to
actual allowed-env policy, Manual/Guided/explicit automatic approvals, hard
denials, read-only/side restrictions, protected paths and all-role budgets.

The service captures configured Home's canonical path and directory device/
inode as the immutable `homeRoot` of an ordinary Local chat. SDK/TUI/desktop
share that binding. Replaced, missing or aliased roots fail; never choose a
new Home, previous project or state directory instead. Project-free Remote
and Sandbox sessions cannot silently acquire this Local root. Private
root-less tool-less roles and settings-only metachat retain their own boundary.

Ordinary Home-backed chats may use applicable files, commands, Agent terminal
output, structured data and explicitly configured global tools. The private
User console stays distinct and never becomes model context. Home contents
and repository instructions are not automatically enumerated or injected.
Repository-only knowledge, managed workspaces and project continuation still
require an actual explicitly selected repository/project.

The user explicitly requested one exception, specified in
`chat-repository-binding.md`. A Home chat acquires a real project only after an
observed successful file write inside a real Git repository nested below Home
(never Home itself), plus an existing project at that exact path, an actual
user confirmation, or the user's saved "don't ask again" preference. The move
is a typed service rebind of the whole chat tree; it is never synthetic, never
inferred from earlier chats and never a tool grant.

Browser control already supports a null project: preserve its exact native
host lease, explicit Agent-control toggle, current page handles, ordinary tool
approval and no-replay revocation. A chat must not falsely claim a project is
required to discover or use that capability. Git/GitHub commands can run from
Home but need explicit repository arguments or a user-selected checkout;
never infer one from a prior chat or silently authenticate/switch accounts.
Existing typed project publication remains separately reviewed.
Home-dependent MCP calls bind the captured directory into their permission
resource digest. A pre-Home null-root remembered grant cannot silently approve
the new working directory. Legacy file/tool/MCP clients prepare Home through
the owning command path before workspace-dependent discovery or execution.

## Owned writes and retention

Model-only Home conversations stay independent. Acquire a retained Home
writer intent before the first actual workspace-writing tool is admitted;
wait cancellably for overlapping owned roots rather than paying for another
model retry. Actual filesystem/command work keeps the same captured root,
permission revision and cancellation ownership through final acknowledgement.
An actual user response owns its one-shot admission before asynchronous root
checks; a competing answer cannot consume the same approval. Legacy bounded
Max advice uses the same Home claim, fresh authorization and executor binding,
and cannot override an actual human response while waiting for the root.
Read-only browsing and model calls do not become filesystem writers.
The exact already-authenticated private User console remains usable for actual
user inspection after Agent cancellation. Its original root/Env/owner and
attachment checks still apply; this neither launches a new independent console
through a held root nor exposes private console bytes to a model.

Writer observations belong to the profile/root independently of source-session
retention. Unknown command/process cleanup or a lost active owner quarantines
the captured root after restart or source deletion. Only an exact settled
owner or exact actual-user Home-writer inspection can release it; model advice,
navigation, deletion and a new session cannot manufacture cleanup. Different
profiles sharing the same physical Home/overlapping repository roots must
observe the same writer exclusion without sharing transcripts or credentials.
Ordinary session Resume is not a Home-writer acknowledgement. Inspection does
not resume held prompts or turn an unknown cleanup observation into success.

## Persistence and qualification

Protocol/schema 72 adds typed Home bindings and independent writer records
through versioned append-only events and a strict atomic migration marker.
Preserve legacy ciphertext, grants, receipts, budgets, models and preferences.
Existing project-free Local chats bind the configured Home at their next
explicit use, not to an inferred project. Binding is execution context, never
authentication, an approval or a user answer.
Approval handoff includes the exact Home identity. The Local executor verifies
it again before filesystem/command work, including immediately before a full
file publication; neither SSH nor Sandbox accepts that controller-Home binding.
Older clients refuse protocol-72 state. This is a forward, non-destructive
migration, not a downgrade that strips new bindings or requires deleting state.

Generated tests must prove actual approved `pwd` and file work in Home,
unchanged null project identity, explicit GitHub repository targeting and
root-less browser control; Manual/automatic/denial/read-only behavior; no
other-project context; parallel model turns and serialized actual writers;
failed cancellation, root replacement, migrations/recovery and independent
quarantine after deletion; and actual packed SDK/TUI/desktop paths. All tests
use generated homes, repositories, credentials, shells and loopback endpoints,
never the user's real Home contents, GitHub account or browser.
