# Owned budget wind-down and accepted-work checkpoints

Status: protocol/database 39 source integration. This is not a new qualified
archive or completed milestone. System One/Max and final native/source
acceptance remain separate gates.

Reuse maintained pi-ai, TypeBox, Node/abort/crypto and the existing event store,
worker, ledger, filesystem capture and job supervisor (MIT). Reuse the
existing system Git executable (GPL-2.0-only) and `ProjectService.reviewedCommit`
temporary-index path. No dependency, hidden agent loop, billing ledger,
credential or filesystem authority is added.

## Explicit policy and complete capacity

`settings.winddown` starts disabled, with no selected model. The user selects
one exact available Local concrete model, separate hosted/network metadata
consent, a positive complete output-token bound and deadline. This does not
select a generative model, change autonomy, lift limits or grant Git.
Remote/native finishing remains unavailable, never a Local fallback.

Finite kupo needs that qualified policy. Ordinary configured finite Local
turns can use it too. Admission captures the original profile/session/turn,
source directory identity or null, task/attachment digest, concrete model and
working window, policy and complete future metadata/output envelope.
The existing `planBatch` appends the entire hold with the real owning intent
before yielding. Compound admission includes its router and finishing holds
in that one batch; it cannot overlap two independent views of capacity.

Every actual router/solver/draft/critic/revision/finishing call uses the same
session/profile/global budget authority. Input is estimated, actual output
limits are forwarded, provider reports reconcile once, and billed USD stays
unknown unless supplied. Fresh user-approved rates are required under USD
limits. Consuming a plan rechecks all current held/actual capacity before
transfer; a newly stricter cap below it cannot be bypassed by shrinking an
input estimate. An undispatched plan is not a call or a provider report.

## One bounded finishing role

When the actual next ordinary call or complete route batch cannot fit, stop
ordinary work. Transfer only the original finishing hold, atomically with
its actual entry/start, to one tool-less `checkpoint` role. Recheck the exact
owner, mode, Local boundary, model, privacy, prices and complete envelope.
Unknown/over-limit ordinary work blocks an additional finishing request.

The finishing model receives only canonical all-role count/token aggregates,
the original task digest and a digest of the complete call metadata set.
It receives no task text, source code, chat history or router explanations.
That explicitly selected metadata scope is not silent history truncation;
original task/context/results remain retained. Worst-case safe counts and
the complete role set are reserved before admission.

Accept only bounded JSON summary data after complete reported usage settles.
Unreported/stopped/deferred output is partial and held, not a ready or free
checkpoint. Invalid/over-limit advice remains charged and cannot approve Git.
The owner cannot resume ordinary inference or tools using leftover capacity.
The original task ends visibly interrupted, not falsely completed.

Unused undispatched holds release only when the canonical owner ends.
Source deletion/restart cannot refund consumed or unknown work. Restart
retains partial observations, never invokes a replacement finishing model.

## Separate actual-user Git review

A summary is not source acceptance, code quality, validation or Git permission.
The user separately selects retained **applied** candidates whose source
acceptance actor is the actual user. Staging, a model/critic pass or matching
output contracts cannot supply that acceptance.

Preview captures exact original Local source/project/worktree identity,
current repository/common directory/HEAD/branch/index state, accepted source
records, actual regular-file bytes and executable modes, current caller
permissions/folder policy, exact message and a new non-protected local branch.
Changed source bytes, aliases, duplicate/protected paths, stale roots,
read-only modes, hard denials, busy writers and unconfirmed work block it.
Project-free/deleted/moved sources never inherit another checkout.

The actual-user commit command persists its exact review and independent job
before effects. It uses the existing temporary-index `read-tree`,
`hash-object`, `commit-tree --no-gpg-sign` and zero-old-ref compare-and-set
helper. Hooks/filters do not execute. No checkout, real index/HEAD replacement,
push, merge, rebase, force update or branch deletion occurs. No tool attribution
is added. A competing branch is never overwritten.

Retain the prepared commit/publication intent before ref creation, actual
publication acknowledgement and final ref/blob/source readback. Stop and
authority checks surround preparation/publication/completion. A late stop,
lost receipt or changed ref is partial, not fictional rollback or success.
Prepared unreachable objects or an already-published branch may remain.
The exact source is quarantined after possible unconfirmed publication.
Original commands return their retained outcome instead of replaying Git.

This validates accepted bytes/root/ref mechanics. No new project tests or
calibrated code-quality proof is implied. The Local supervisor still cannot
prove detached/reparented containment or exclude hostile external writers.

## Independent state and shared clients

`winddown.recorded` retains its versioned input, actual role input/raw result
and separate Git review/publication under an independent artifact key.
Budget plans/calls stay in the profile budget compartment. Original report
bytes cannot be replaced through metadata editors. Active held/model/Git
ownership prevents report deletion; explicit later deletion does not erase
model charges. Artifact export schema 8 includes actual role/Git observations.

Schema 39 is additive. Schema-38 compound roles/tests, scoped files, receipts,
budget entries and ciphertext are preserved through migration failure/reopen.
No old reservation is relabeled or replayed. Actual controller SIGKILL before
and after ref creation preserves original partial intent without another
model, ref publication or source/index/HEAD reset.

SDK `winddown.status/list/read`, exact stop/decline, `commitPreview/commit`
and `waitCommit` are canonical. CLI and shared `/winddown` expose separate
`confirm-git` review, not model-cost consent. Desktop configures the policy in
Settings / Budgets, enables eligible finite kupo controls from service
readiness, and reviews accepted bytes/new branch under Candidates / Budget
wind-down checkpoints. Actual TUI keys use the same confirmation and edit
only retained report metadata.
