# Reviewed compound workflows

Status: shared service/SDK implementation in progress. The public path now
owns real bounded calls, conditional Cascade/Critique and separately approved
project tests. CLI/TUI/desktop review, failure/recovery hardening and finite
wind-down remain qualification gates. Private prototypes and native execution
checks do not establish this public workflow's acceptance.

## Authority and reuse

Reuse maintained pi-ai, TypeBox, Node/Node-PTY and the existing worker,
supervisor, candidate byte/base helpers and event store (MIT), plus the
existing system Git executable (GPL-2.0-only). Do not add an agent framework,
hidden workflow database or separate cost ledger.

The actual user selected **approved project tests in owned worktrees,
respecting Manual permissions**. Critique must cover the current request's
**plan, architecture and implementation**, not merely JSON validity or a
passing command. These are complementary observations, not interchangeable
quality or permission proofs.

The control plane remains authoritative for model bindings, approved data
destinations, budgets, cancellation, validation execution and candidate
selection. Every classifier, proposer, critic, revision and escalation uses
the existing bounded worker/receipt path. Model output cannot grant a test,
file operation, another paid role or source acceptance.

## One bounded request

An explicitly reviewed input captures the canonical task/context, selected
source files and bases, actual source root and HEAD, distinct owned candidate
worktrees, configured validation script identity/bytes and the eligible
profile/model policy. No previous project, dirty worktree or implicit Remote/
Sandbox mapping is substituted.

The classifier selects only a declared eligible route and concrete bindings.
Its actual result, not a prewritten role sequence, determines the next roles.
Reasons stay outside later solver/critic context. A proposal retains bounded
plan and architecture text alongside its canonical base-bound patch. Earlier
proposal, critic and validation text enter only explicitly selected untrusted
data fields, never new system instructions.

Cascade validates the efficient proposal and permits one configured
escalation on a known validation failure. Critique uses one eligible
read-only/tool-less critic and at most one same-solver revision. The critic
receives the actual task, plan, architecture, implementation and retained test
evidence, with issues attributed to those areas. A passing critic cannot
override failed required tests; rejection or unknown results cannot silently
dispatch another model.

## Staging and real validation

Source and candidate roots remain distinct. Rejected candidates and their
actual attempts/results stay independently retained, never reset into the
user's source or silently removed.

The current public path requires selected source bases to match both clean
candidate HEADs. A selected dirty source snapshot is rejected before any
model call instead of being silently omitted from validation. Unselected
source/index edits are preserved, not copied into the candidate. Validation
therefore covers the reviewed candidate on that committed base, not an
unreviewed mirror of the whole source worktree.

Before candidate code is staged or tested, disclose the exact candidate bytes,
owned destination, configured command and execution boundary. Manual/Guided
requires an actual user decision unless the complete operation already fits
explicit bounded user grants. Hard denials and folder restrictions win even
after a user/model recommendation. Neither the initial cost consent nor a
valid model proposal is staging or command permission.

Reuse the exact reviewed candidate stage path and normal owned command
supervisor. Validation binds the command, candidate, root, original user or
delegation actor and result. Recheck candidate bytes after the command;
formatters/test mutations cannot silently become accepted model changes.
Retain stdout/stderr within existing command limits, exit/outcome and actual
known cleanup. Test output is untrusted data. Local/SSH detached/reparented
containment remains explicitly unproven.

Public roles use the existing root-less/read-only worker loop and a distinct
public owner flag. The private owned-role protocol cannot adopt validation
authority. After a complete metered proposal, the same worker waits for the
actual-user stage/test decision. Only then can it receive one exact
validation operation and request a fresh command boundary. Host process
groups still use the existing supervisor and disconnect cancellation.
Before and after execution, compare exact proposal bytes, canonical root,
HEAD/branch/common directory and bounded Git status/worktree/index evidence.
Tracked, index or nonignored path mutations cannot become a passing result.

Each public role has an 8-KiB lossless text-result envelope. The next role's
complete context reserves worst-case JSON escaping, including up to 16 KiB
of actual command output. Larger command output remains retained under the
ordinary command limit but blocks paid continuation; it is not silently
trimmed into critic evidence. Exact per-role output-token bounds remain
separate from these byte limits and provider-reported usage.

Passing configured tests establishes only those tests against those bytes.
It is not calibrated model quality, independent training, user source
acceptance or Git authority. A final recommended candidate still needs its
separate exact actual-user source-application review.

## Eligibility evidence

Provider family/vendor/version declarations remain informational and explicit
inspection does not become ordinary discovery. Aliases, names, provider
prefixes, matching contracts and generated fixtures never establish model
independence.

Independent critique needs an actual-user-reviewed, source-backed lineage
assertion for the exact concrete model bindings. Retain the source, digest,
review actor, scope and limitations separately from model advice. This is an
eligibility policy based on reviewed evidence, not a Moguri proof about
unobservable training. Missing evidence stays unknown; changed bindings or
resolved versions invalidate the review. Never manufacture a family from a
display name or accept a model's own assertion as the review.

## Durable calls and failure

Add versioned public intent, routing/role bindings, validation reviews,
candidate selections and outcomes to the existing append-only event stream.
Use an additive migration with exact ciphertext/receipt/restart tests.
Reports, raw inputs/results and candidate provenance need independent grants;
source session deletion is not cancellation or deletion of retained work.

Schema 38 adds `compound.recorded`, public control-turn ownership, validation
job ownership and independently copied `compoundOrigin` candidate grants.
The existing budget plans, starts and completions remain the only model
ledger; private and public paths share its owner/model/bound validation,
not each other's execution authority. Ordinary solver history excludes the
entire public control turn, including critic/revision/escalation results.
Artifact export schema 7 carries original workflow/role/test records and
blobs, plus candidate origin copies. Metadata editing cannot replace those
inputs/results. Deleting a report retains only the original command intent
needed to reject paid replay.

The router starts with its exact hold. Its actual acknowledged selection
atomically appends the complete selected route's future hold batch before
another role can start. Conditional roles are skipped without invented
usage, and canonically undispatched holds release only when the real owner
ends. Recommendation remains pending until that worker's terminal
acknowledgement; a stop cannot be relabeled as a completed recommendation.

Reserve every actual model role atomically with its start, and calculate each
complete same-turn future hold set before yielding. Unknown or lost usage
retains capacity. Finite public kupo remains blocked until the separately
authorized wind-down/checkpoint lifecycle is wired; reservation primitives
alone cannot enable it.

Cancellation stops the actual model/validation owners, invalidates pending
reviews and preserves requested/acknowledged/failed/partial states. Late
receipts may reconcile accounting but never resume roles or upgrade a partial
workflow. Original commands, paid calls, candidate writes and test commands
are not replayed after receipt loss or restart. New roots/policy, human
intervention, storage failure, unknown output or lost cleanup block further
effects and require inspection.

## Cross-client acceptance

SDK capabilities are canonical and browser-safe; CLI/shared slash, actual
TUI and desktop expose the same reviewed source, plan/architecture/patch,
model provenance, validation command/permission/result, conditional roles,
candidate selection and separate application. Held queues and actual-user
drafts must survive blocked or failed workflow admission.

Use generated model/lineage/command fixtures, not personal data or live
inference. Cover classifier-to-role dispatch, real passing/failing tests,
plan/architecture critique, conditional escalation/revision, unknown lineage,
unreported/late usage, hard denials, concurrent clients, stale reviews,
source/index/HEAD preservation, lost receipts, real controller loss and
recovery without another model, test command or filesystem publication.
